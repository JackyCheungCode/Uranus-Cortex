# 前端页面验收清单

每个页面或较大的交互改动在视为完成前，逐项检查。标为“不适用”的项目应说明原因。

## 页面与视觉
- [ ] 页面目标、用户主要任务和主要操作清晰。
- [ ] 使用 Carbon 官方组件和推荐模式；组件选择无明显不合理之处。
- [ ] 使用 Carbon 主题与 token；没有未经说明的硬编码颜色、间距、字体或阴影。
- [ ] 标题、说明、操作区、内容区和反馈区层级一致。
- [ ] 图标来自 Carbon Icons；没有 Emoji 作为功能图标。
- [ ] 没有引入未经批准的第二套 UI 库或重复设计令牌。

## 交互与状态
- [ ] 所有可见按钮、链接、筛选、表单和弹层均有真实的前端交互。
- [ ] 加载、空结果、成功、校验失败、请求失败、禁用等适用状态完整。
- [ ] 表单具备标签、必填说明、校验和可读的错误提示。
- [ ] 破坏性或重要操作有适当的确认和反馈。
- [ ] Mock 行为与真实服务状态清楚区分；没有伪装成真实 API 或持久化成功。

## 响应式与无障碍
- [ ] 已检查宽屏、常见桌面尺寸、窄屏及缩放/重排。
- [ ] 没有意外的横向溢出、被遮挡内容或不可用控件。
- [ ] 键盘可以完成主要任务；焦点可见且顺序合理。
- [ ] 控件有可访问名称，表单错误与字段关联。
- [ ] 使用语义元素和合理的标题层级；状态不只依靠颜色表达。
- [ ] 考虑 reduced-motion 和对比度。

## 架构与质量
- [ ] 页面只负责编排；业务规则没有不必要地堆积在 JSX 中。
- [ ] 模块通过公开接口协作，没有跨模块导入内部路径或循环依赖。
- [ ] TypeScript 类型明确，没有不必要的 `any`。
- [ ] UI 通过服务接口读取数据，Mock 数据与 UI 解耦。
- [ ] 测试覆盖变更行为与关键状态。
- [ ] 已执行可用的 typecheck、lint、test、build、audit；未运行项及原因已记录。
- [ ] 没有密钥、生产数据、未授权外部调用或生产环境变更。
- [ ] 文档、截图/预览（若适用）及已知限制已更新。
