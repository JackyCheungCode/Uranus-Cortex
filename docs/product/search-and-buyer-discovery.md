# 搜索与潜在采购商发现模块：开发需求与实施方案

- 文档状态：需求基线，供分阶段实施与验收
- 项目：Uranus-Cortex
- 目标技术栈：React + TypeScript + Vite、IBM Carbon、Cloudflare Workers/Pages、Supabase（具体后端方案仍需分阶段评审）
- 设计原则：证据优先、供应商可替换、默认控费、增量处理、全程可追溯
- 边界：本文是需求与架构方案，不代表功能已经实现，也不授权部署生产环境或修改生产数据。

## 1. 项目目标

建立一套可配置、多供应商、可观察、可控成本的搜索与客户发现能力，帮助识别可能从中国采购二手服装的海外企业，并将有证据支持的候选客户交给 CRM 审核和跟进。

系统覆盖：
1. 管理多个网页搜索、SERP 和 AI 搜索服务。
2. 通过可视化条件构建器创建、检查、编辑和复用搜索表达式。
3. 搜索执行过程中动态显示新发现的网页及处理状态。
4. 提取网页正文、识别企业和公开商务联系信息。
5. 评估业务匹配度与采购意向，并为重要结论保存证据。
6. 通过缓存、去重、幂等任务、预算和停止规则减少重复浪费。
7. 支持人工审核、纠错、排除、客户跟进和反馈闭环。

优化目标不是网页总数，而是**单位成本发现的新增、真实、符合业务条件的企业数量**。

## 2. 范围与非目标

### 本期范围
- 搜索服务商管理与适配器接口。
- 搜索条件构建器和统一查询模型。
- 国家 / 地区选择地图。
- 动态网页结果列表与搜索任务状态。
- 网页抓取、正文提取、结构化企业信息提取。
- 证据记录、企业去重、候选客户评分。
- 缓存、预算、调用记录、任务幂等、失败处理。
- 人工审核与 CRM 入库边界。

### 暂不默认包含
- 未经确认的自动外联、群发邮件或社交平台自动私信。
- 绕过登录、付费墙、验证码、访问限制或网站条款。
- 将搜索摘要或 AI 推断直接视为采购事实。
- 假设所有服务商完全兼容或拥有永久免费额度。
- 自动部署生产 Worker、修改生产数据库 schema 或写入生产数据。
- 将未经审核的候选客户自动视为正式客户。

## 3. 核心用户流程

1. 用户在搜索服务设置中配置一个或多个服务商密钥，并测试连接。
2. 搜索页只显示已配置、测试成功且启用的服务商；无可用服务时显示空状态和设置入口。
3. 用户通过可视化构建器设定关键词、国家 / 地区、企业类型、产品类型、采购信号、语言、网站范围、排除词、时间范围和结果限制。
4. 系统实时生成统一查询表达式，并提示当前供应商的语法兼容性。
5. 用户提交任务前查看供应商、预算上限、预估调用次数和回退策略。
6. 搜索运行后，网页逐批进入动态结果列表。
7. 每个网页独立进入抓取、正文提取、企业识别、证据验证和客户评估队列。
8. 系统将结果与已有网页、企业档案比较；重复记录合并证据，不重复创建客户。
9. 候选企业进入审核队列；用户可以确认、修改、排除或加入 CRM。
10. 用户反馈相关性、联系方式有效性、询价、无需求或成交结果，用于后续优化。

## 4. 搜索供应商管理

### 4.1 适配器架构
采用 provider registry + provider adapter。每个服务商独立实现请求转换、认证、响应解析、错误分类、能力声明和用量信息（如服务商支持）。

候选服务商包括 Tavily、Exa、Firecrawl、Brave Search API、Serper.dev、DataForSEO，以及后续其他 SERP、网页搜索或网页提取服务。候选名单不代表一次性全部接入。首批应使用同一组测试查询比较新增合格企业率、重复率、响应时间、正文可用性和成本。

接入前必须核实官方 API、价格、免费额度、注册条件和商业使用条款；所有价格和额度信息应记录官方来源与最后核实日期。

### 4.2 统一设置页面
每个服务商展示名称、类别、能力说明、配置状态、连接测试状态、启用状态、默认状态、密钥录入 / 更新 / 删除、最后测试时间、最近错误、系统内部调用量和成本估算。官方余额或配额只有在 API 能可靠查询时才显示；否则明确标记“不可实时获取”。

### 4.3 搜索选择器显示规则
只有同时满足以下条件的服务商才进入搜索下拉框：
1. 认证信息已配置；
2. 连接测试成功；
3. 用户启用该服务；
4. 服务能力与当前任务兼容。

未配置、测试失败或禁用的服务商不显示在搜索下拉框，但仍可在设置页查看和配置。无可用服务时显示空状态及设置入口。密钥失效时标记为不可用并解释原因。

### 4.4 费用与回退
- 默认不自动切换到可能收费的备用服务。
- 用户可选择禁用回退、仅使用免费 / 预算内服务，或明确允许指定备用服务。
- 每次任务执行前检查剩余预算；达到上限后停止新的付费调用。
- 记录系统观察到的请求和估算费用；服务商账单不可查询时，明确区分估算和实际账单。

### 4.5 密钥安全
- API Key / Token 不得放入前端 bundle、浏览器 localStorage、客户端可读数据库字段、日志或 Git 仓库。
- 浏览器只读取“已配置 / 未配置、测试结果、脱敏标识”等状态，不返回完整密钥。
- 搜索请求由后端执行。服务端密钥存储方案需在部署设计时明确。
- 对密钥更新、删除和测试操作实施权限检查与审计。
- 不要求用户在聊天中发送密钥。

## 5. 可视化搜索条件构建器

### 5.1 交互原则
采用双向同步：
- 用户修改条件时，统一查询表达式实时更新。
- 用户可以切换到语法编辑模式直接修改表达式。
- 可解析语法反映回条件面板。
- 无法解析的片段必须保留并提示，不可静默删除或改写。
- 支持保存、命名、复制和复用搜索方案。
- 地图选择的国家 / 地区同步写入统一查询模型。

### 5.2 条件范围
基础条件：主关键词、同义词、必须包含词组、AND / OR / NOT 逻辑组、国家 / 地区、语言、潜在企业类型、产品范围、采购信号、结果数量、时间范围、结果类型和正文提取选项。

高级条件：必须包含 / 排除关键词、指定 / 排除域名、site 限定、网页发布时间、搜索语言和地区参数、最大 API 调用数、最大抓取页数、最大 AI 分析数、任务时限、预算、备用服务和自动停止条件。

企业类型应包含进口商、批发商、分销商、零售商、分拣厂 / 回收企业、电商卖家及其他候选类型，不预设某一类型永远优先。产品条件应覆盖混装 / 未分拣、分拣 / 分级、季节和服装类别。

### 5.3 统一查询模型与供应商兼容性
不将原始搜索语法作为唯一数据源。保存结构化条件，由适配器转换为目标 API 支持的参数或语法。

每个供应商声明是否支持国家 / 语言参数、时间过滤、精确词组、OR、排除词、域名过滤、正文 / 摘要、发布日期、分页、流式输出和用量查询。

不支持的条件必须提示，并采用明确的降级策略，例如拆分查询、结果后筛选或要求用户确认；不能假装条件已在搜索引擎侧生效。

## 6. 国家与地区地图选择器

### 6.1 地图交互
- 使用 OpenStreetMap 生态地图底图；正式部署前确认瓦片服务的许可、使用政策、容量和供应商方案。
- 使用独立 GeoJSON / 多边形边界数据实现国家 / 地区点击与高亮。OSM 底图本身不等于可直接控制填充颜色的边界图层。
- 选中区域后高亮其领土，取消选择后恢复；列表、地图和已选标签双向同步。
- 支持多选、国家搜索、缩放、键盘可访问的列表替代方案和移动端布局。
- 颜色不能作为唯一选中状态提示；必须提供勾选、文本标签和无障碍状态。
- 地图组件和边界数据可替换，业务逻辑不应耦合到单一地图供应商。

### 6.2 中国相关选项
必须提供四个独立选项：
- 中国大陆（内部 ID 建议：CN-MAINLAND）
- 中国香港（HK）
- 中国台湾（TW）
- 中国澳门（MO）

以上内部 ID 是应用约定，不代表它们都是 ISO 标准代码。中国大陆边界需使用适当的独立几何数据，避免选择大陆时错误地把香港、澳门一并高亮。边界数据来源、版本、许可和地理呈现政策需在实现前记录并评审。

### 6.3 圆形旗帜
所有国家 / 地区选择项统一使用圆形旗帜图标，在列表、已选标签和搜索条件摘要中保持一致。旗帜仅作辅助识别，不代替可访问名称；需提供完整文本标签和屏幕阅读器名称。

## 7. 动态搜索网页列表

### 7.1 实时体验
任务创建后立即显示状态；每批结果返回后立即追加到列表，不必等待所有关键词或供应商完成。

建议字段：标题、URL、域名、摘要、发布日期（若有）、发现时间、来源供应商、命中的关键词 / 条件、抓取状态、正文提取状态、企业识别状态、评估状态、去重状态、关联企业、失败原因和证据入口。

支持按国家、来源、处理状态、企业匹配度、发现时间筛选和排序；支持暂停、继续、停止、重试失败步骤和查看统计。

### 7.2 实时传输
供应商未必支持逐条流式结果。系统保证“结果批次返回后尽快展示”，不承诺每个供应商都能在其内部产生单条结果时立即推送。

可评估 SSE 或 Supabase Realtime。方案应按 Worker 任务执行模式、连接时长、重连行为和部署限制确定。结果必须先持久化或可恢复，再推送事件；前端重连后可按任务 ID 补取状态和结果。

### 7.3 状态机
任务状态：queued、running、paused、completed、completed_with_warnings、stopped、failed。

网页状态：discovered、fetch_queued、fetching、fetched、extracting、extracted、verifying、assessed、skipped、failed。

状态转换必须明确、可观测、可重试；重复事件不得导致重复写入或重复收费。

## 8. 网页提取与客户识别

### 8.1 处理流水线
1. 网页分类：企业官网、产品页、批发页、采购公告、商业目录、商务主页、新闻或无关页面。
2. 在许可与安全策略允许的前提下获取公开网页内容。
3. 清理导航、脚本、广告等非正文内容，保存正文版本和内容哈希。
4. 使用规则 + AI 提取结构化字段。
5. 为重要字段绑定来源 URL、引用片段、抓取时间和提取方法。
6. 验证企业身份、官网归属、联系方式与业务证据。
7. 与全局企业库去重，合并新证据。
8. 计算业务匹配度和采购意向强度。
9. 进入人工审核队列，再按用户操作写入 CRM。

### 8.2 企业信息
提取企业名称、品牌 / 别名、官网、域名、国家、城市、公开地址（有可靠来源时）、企业类型、业务描述、经营品类、批发 / 进口 / 分销证据、混装或分拣服装相关性、公开商务邮箱、电话、联系表单、商务主页及其来源。规模、经营年限等信息仅在有可靠来源时记录。

### 8.3 采购信号
单独记录明确寻找供应商的表述、采购需求 / 招标 / 供应商征集、进口或大宗采购证据、产品 / 等级 / 数量 / 市场 / 时效要求（网页确实提供时），以及来源发布日期和时效状态。

不能因为企业经营服装就断言它采购二手服装；不能因为网页出现邮箱就断言它是采购负责人；不能将 AI 推断标记为已核实事实。

### 8.4 字段可信状态
每项重要信息应标记为 verified（经规定流程确认）、source_supported（来源明确但未独立验证）、inferred（模型推断）、conflicted（来源冲突）、not_found（未找到）或 stale（超过复核期限）。

验证成功只代表相应验证范围，不代表企业一定有采购意向。

## 9. 评分与人工审核

业务匹配度和采购意向强度分开评分：
- 业务匹配度：企业类型、产品类别、国家 / 市场、业务证据与供货范围的吻合程度。
- 采购意向强度：明确采购信号、信号新鲜度、证据质量和交叉验证情况。

评分应可解释，显示命中证据、扣分原因和缺失项。没有采购信号时，不得仅因企业属于相关行业而赋予高采购意向分。

审核分流建议：
- 高匹配且证据充分：优先审核；
- 相关但缺少采购证据：继续补充搜索；
- 信息冲突或身份不确定：人工核实；
- 明显不相关：排除并记录原因。

未经人工确认的候选企业不自动视为正式 CRM 客户。

## 10. 防重复与成本控制

### 10.1 查询缓存
生成规范化查询指纹，包含结构化查询条件及版本、服务商、搜索模式、地区、语言、时间范围、分页和数量限制。相同指纹在有效期内优先复用缓存。条件或服务商不同，不应误命中缓存。时效性强的采购需求缓存期限应更短。

### 10.2 URL 与正文去重
- URL 规范化处理默认端口、片段、追踪参数、尾部斜杠和可验证的 canonical URL。
- 不应盲目删除所有查询参数；部分网站依赖参数区分内容。
- 保存正文哈希和版本。内容未变化时复用提取结果；内容变化时只重跑受影响步骤。
- 同一 URL 可能对应不同语言或内容版本，必要时保留独立版本。

### 10.3 企业去重
匹配优先级：
1. 经验证的企业注册编号等稳定标识；
2. 已验证官网域名；
3. 企业名称 + 国家 / 地址 / 电话等多字段一致；
4. 品牌别名、邮箱域名和页面内容等辅助证据；
5. 不确定时交人工审核。

不能只凭名称相似自动合并。企业合并须保留别名、来源、合并理由和可撤销的操作历史。

### 10.4 AI 缓存与任务幂等
记录输入内容哈希、提示 / 规则版本、模型标识和输出版本。相同输入和相同处理版本可复用结果。使用幂等键、唯一约束、锁和有限重试避免重复任务、重复写入和并发重复调用。

缓存复用需考虑供应商、模型版本、提示版本和数据新鲜度；不得把旧评分当作最新评分。

### 10.5 停止条件
每个任务支持最大搜索 API 调用次数、最大结果数 / 抓取页数、最大 AI 分析数、单任务 / 每日 / 每月预算、最大运行时间、连续若干批无新增合格企业时停止、重试次数和错误率阈值。“连续三批无新增合格企业”可作为可配置示例，不应硬编码为所有任务的规则。停止后说明原因并保留已有结果。

### 10.6 核心指标
新增合格企业数 / 搜索调用次数、每个新增合格企业的总估算成本、缓存命中率、URL 重复率、企业重复率、误合并率、抓取和提取成功率、采购信号命中率、人工确认率、各供应商独立新增企业数、响应时间、费用与任务停止原因。

## 11. 建议数据实体（逻辑模型）

以下是逻辑实体建议，不是已执行的数据库迁移。实际表结构、RLS、索引、保留策略和租户隔离需在 Supabase 设计阶段评审。

- search_providers：服务商类型、启用 / 默认状态、能力和非敏感配置。
- search_tasks：用户、查询模型、供应商、预算、状态、统计和时间戳。
- search_task_events：状态变化、进度、错误和可恢复事件。
- search_cache：查询指纹、结果引用、有效期。
- discovered_pages：规范化 URL、标题、摘要、来源、任务关联和处理状态。
- page_versions：正文哈希、抓取时间、正文存储引用、版本与内容差异。
- processing_jobs：幂等键、阶段、锁、重试和错误信息。
- companies：去重后的企业主档案。
- company_aliases：品牌名、别名、域名和标识。
- company_contacts：公开商务联系方式、类型、来源、验证状态和复核时间。
- company_evidence：字段 / 采购信号、原文片段、来源 URL、时间和可信状态。
- buyer_assessments：业务匹配度、采购意向分、依据、规则 / 模型版本。
- crm_activities：审核、纠错、排除、联系记录和后续结果。
- usage_ledger：每次供应商调用、计量单位、估算成本和实际费用（若可取得）。
- suppression_records：不联系、删除、纠错或其他必要限制记录。

密钥不应以明文存放在普通业务表中。正式 schema 必须实施最小权限、RLS / 服务端权限边界、敏感字段保护与审计。

## 12. 隐私、安全与网页抓取约束

- 仅处理业务目的所需且来源合法的信息，遵守适用的数据保护、隐私和营销法规。
- 记录来源、处理目的、采集时间和保留期限；提供纠错、删除和禁止联系机制。
- 尊重网站条款、访问控制、robots / 抓取政策和供应商许可；不绕过登录、付费墙、验证码或技术访问限制。
- 网页是非可信输入，可能包含提示注入或恶意内容。AI 提取流程必须把网页内容视为数据而非指令，不能允许网页内容泄露密钥、调用工具或改变系统策略。
- 抓取服务应防范 SSRF：限制协议、阻止私有 / 环回 / 链路本地地址、重定向后重新验证目标、限制响应大小与执行时间。
- 对日志脱敏，不记录完整密钥；设置速率限制、并发上限、超时和内容大小限制。
- 联系方式仅在必要且合法的业务场景中使用；支持退订、禁止联系和数据保留政策。

## 13. IBM Carbon 与前端规范

- 正式产品界面遵循仓库 AGENTS.md 和 docs/design/carbon-standards.md。
- 优先使用 @carbon/react、Carbon tokens、Carbon Grid 和官方交互模式。
- 不引入第二套 UI 设计系统；地图 / 地理组件作为明确的例外依赖单独评审。
- 国家选择器必须提供地图之外的可访问列表，支持键盘、屏幕阅读器、可见焦点和窄屏布局。
- 搜索列表覆盖加载、空结果、成功、部分成功、失败、暂停、预算耗尽、权限不足和重连状态。
- 状态不可只用颜色表示；动态列表应避免屏幕阅读器被每条新结果反复打断。
- 新增组件需补充行为测试、键盘 / 可访问性检查和响应式测试。

## 14. 分阶段实施路线

### 阶段 0：基础核验与设计确认
核实现有分支、依赖、Worker 配置和部署边界；核实候选供应商官方 API、价格、免费额度、数据使用权和注册条件；选定首批供应商、预算策略、密钥存储、任务执行方式和地图边界数据；确定 Supabase 权限、RLS 和保留策略。输出架构决策记录，不在核验前部署生产环境。

### 阶段 1：搜索基础
服务商注册表、密钥设置和连接测试；已配置服务商选择器；结构化查询模型、基础条件和实时语法预览；预算、调用记录和统一错误状态。
验收：无可用服务时空状态正确；未配置服务不出现在搜索选择器；密钥不会返回浏览器。

### 阶段 2：地图与动态网页列表
OSM 底图、合规边界数据、多选和高亮；中国大陆 / 香港 / 台湾 / 澳门独立选择；搜索任务状态机、动态结果列表、恢复与停止。
验收：地图与列表双向同步；结果批次返回后及时显示；刷新后可恢复任务状态。

### 阶段 3：网页与客户提取
网页抓取、正文提取、结构化字段和证据记录；企业去重、联系方式验证状态、采购信号；匹配度 / 采购意向分开评分和人工审核队列。
验收：重要字段能回溯证据；AI 推断不会标成已验证；重复网页不会创建重复企业。

### 阶段 4：防重复与成本优化
查询、正文、AI 结果缓存；幂等任务、有限重试、预算和停止规则；供应商增量产出与单位成本报表。
验收：重复任务复用缓存；内容变化触发有针对性的重新处理；达到预算后不再发起新的付费调用。

### 阶段 5：CRM 与反馈闭环
审核通过后创建 / 更新 CRM 客户；记录人工反馈、跟进状态和结果；定时复核、采购信号变化监测与受控搜索策略优化。
验收：合并、纠错、删除和禁止联系规则可追溯；自动优化受用户范围和预算约束。

## 15. 通用验收标准

- [ ] 搜索服务只显示已配置、测试成功、启用且兼容当前任务的选项。
- [ ] 条件变化时查询表达式动态更新；未知语法不会被静默删除。
- [ ] 供应商能力差异透明呈现，不支持的条件不会被假装已执行。
- [ ] 地图可多选，地图 / 列表同步，四个中国相关选项独立。
- [ ] 搜索结果按批次动态显示，任务状态可恢复。
- [ ] 每个重要客户字段和采购判断都能追溯来源证据。
- [ ] 网页、企业和处理任务具备去重与幂等机制。
- [ ] API 调用、抓取、AI 分析和估算成本可按任务审计。
- [ ] 达到预算、时间、调用数或无新增价值阈值时能够停止。
- [ ] 密钥仅在服务端使用；前端和日志不暴露秘密。
- [ ] 符合 Carbon、可访问性、响应式和测试要求。
- [ ] 生产部署、生产 schema 变更和真实客户数据写入都经过单独审查与明确授权。

## 16. 尚待决策的架构问题

1. 首批实际接入哪些搜索供应商，是否分别接入搜索与网页提取服务。
2. 搜索任务采用短请求、队列 / 定时任务或 Durable Objects 等机制；需按任务时长、重试和部署限制评估。
3. Supabase 中的用户 / 租户权限、RLS 和数据保留政策。
4. 密钥使用部署时 Worker secrets，还是运行时加密密钥库；取决于是否要求用户在界面动态维护各自凭据。
5. 地图瓦片供应商与国家 / 地区 GeoJSON 的许可、边界精度和版本管理。
6. AI 模型选择、成本上限、提取质量基准和模型输出保留期限。
7. 候选企业自动入库的最低证据要求，以及人工审核职责边界。
